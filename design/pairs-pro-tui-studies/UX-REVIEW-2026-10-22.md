# TUI UX review — from a replay to a multi-session workspace

22 October2026. Bounded outcome: review the consolidated design studio and prototype session navigation using the supplied twelve screen-tab identities and historical log excerpt. Existing Default10 / Omar10 / All20 studies remain intact.

## Review decisions

| Area | Problem | Design decision |
| --- | --- | --- |
| Workspace orientation | Screen tabs expose process names but little actionable context | Persistent session ID + pair + network + fee + tick spacing + strategy; ← opens a searchable session switcher |
| Session navigation | Long tab lists are hard to scan; changing context should not reset a process | One picker, network dropdown, ↑/↓ + Enter, Esc; preserve selected view and log filter per session |
| Information hierarchy | Repeated cache logs obscure position and scheduling decisions | Summary first; separate Events and searchable log excerpt |
| Position interpretation | Current and proposed ticks appear in distant log tables | Side-by-side current and cached target, explicitly without implying execution |
| Process health | A quiet process might be waiting, stopped, healthy idle or disconnected | Separate process state, telemetry and last heartbeat; never infer health from absence of logs |
| Reward feedback | A skip can look like a failure | Show pending amount, threshold and last decision together; retain precise amount in log excerpt |
| Time | Historical timestamps look current if paired with a countdown | Explicit snapshot timestamp; intervals are historical, next live run unknown |
| Shortcut conflicts | ← already steps the backtest replay | Keeper workspace is a separate prototype; backtest keymap stays intact; inputs and tabs keep normal arrow behavior |
| Studio typography | Oversized, tightly tracked headlines compete with previews | Normalize title sizing/spacing; separate direction title and type; readable navigation at narrow widths |
| Studio comparison | Selection state lacks a quick reset | Clear action, persistent set query, visible count and cross-set comparison |

## Prototype

Open [sessions.html](sessions.html). One composition with all20 existing palettes, not another independently maintained set. Twelve supplied sessions remain numbered0–11. Initial view: session8 MEZO/MUSD on Base. The excerpt is associated with session8 for this design based on its MEZO/MUSD follow-mode context; process attribution must be verified before telemetry integration. Other sessions show missing data, not invented holdings. Process statuses are illustrative and labeled DEMO.

Use ← from the console or its buttons to open Sessions; search a pair/network/strategy/ID, filter by network, ↑/↓ to select, Enter to open. `1/2/3` chooses Summary/Events/Raw log. The latter is a normalized supplied excerpt, not a byte-for-byte process stream. Native Tab and Esc are preserved. Session view/filter state lasts within the page; a reload resets this illustrative workspace.

## Next design decision

Use a single session shell around each existing process. Keep GNU screen/process lifecycle independent from view navigation. Before native implementation, select this summary/picker structure and define an adapter for session ID, process state, heartbeat, snapshot age, current/target ranges and structured events. Add per-session log scroll/follow state, bounded buffers, reconnect and exit-code views when attached to real process output. Review at80×24 and120×40 in an actual terminal; this HTML experiment does not establish cell geometry, ANSI support, keyboard transport, background process ownership or telemetry correctness. It launches no processes and sends no commands.
